### SECTION 8 â€” WHAT IS INCOMPLETE OR BROKEN

Based on the codebase:

1. **Zendesk Integration is Placeholder**: The `simulateTicketingIntegration` function in `src/App.tsx` just flashes a success notification and updates the ticket to 'In Review' locally. It does not actually push to Zendesk.
2. **Backfill/Simulator Limits**: The UI contains variables for `backfillLimit`, `backfillDays`, and `backfillMinUrgency`, but the background test files (`test-backfill-bg.mjs`) indicate the simulator and historic backfilling logic might still be experimental or relies on standalone scripts rather than the core UI.
3. **Database Migrations (`001_initial_up.sql`) Missing**: The file tree shows `001_initial_down.sql` but lacks the corresponding `up` migration file for initial tables (it was presumably executed manually).
4. **App Bug/Performance**: `src/App.tsx` does a `setInterval` poll every 5 seconds. The comment notes: *"Poll for new tickets since we moved away from client-side supabase realtime"*. This is a known technical debt/placeholder for a proper WebSocket or Supabase Realtime integration.
5. **Admin Caching Timeout**: The admin cache (`checkIsAdmin`) caches Telegram admins for 1 hour locally in memory and then re-fetches. If the server crashes, or if an admin is quickly added/removed, it might lag.
6. **Support API Key**: Listed in `.env.example` as `SUPPORT_API_KEY`, but no active backend middleware enforcing it for external integrations is currently documented.
